## Local 910B validation attempt

An exact checkout was attempted on Ascend 910B2C with CANN 9.0.0. The clean
build and two separately recorded compatibility-build attempts all exited with
code 2; no `libsgl_kernel_npu.so` was produced, so no import, correctness,
benchmark, or profiling step ran.

The first failure was GNU C++ rejecting global AscendC-only compiler flags.
After a recorded minimal flag patch and disabling the unrelated DeepEP module,
the next failure was an ACL header include-order conflict. A second recorded
compatibility attempt then stopped in the unrelated
`mega_chunk_gdn_kernel_preprocess` CANN linker step with `unknown file type`.
These are environment/build-chain observations, not evidence that PR-592 runs
on 910B or that the causal-conv1d kernel itself is incorrect.

Validation evidence: `validation/ascend-910b/PR-592/evidence/`.
