## Upstream description

# causal_conv1d: PTO-ISA rewrite — variable width, ~2.5× faster, correct at scale

Reimplements `causal_conv1d` (Mamba/GDN depthwise causal conv1d + bias + optional SiLU) on the **PTO tile ISA**. **Drop-in:** same op name and schema, so `pytorch_extensions.cpp` and the Python wrapper are unchanged and no caller changes are needed.

Note: PR-555 = [#555](https://github.com/sgl-project/sgl-kernel-npu/pull/555) also claims an improvement of the same kernel. However, our implementation is **1.49x faster**!

**Why it's better**
- **Faster and correct at scale** .
- **Cleaner** — written on the PTO tile ISA (`Tile`/`TLOAD`/`TMUL`/`TADD`/`TCVT`/`GlobalTensor`, like `mega_chunk_gdn`) instead of hand-rolled AscendC; data movement, fp32 accumulation and pipe sync each read top-to-bottom.
- **Variable filter width** — templated on the accumulator-ring size (compile-time power of two), with width **K as a runtime arg**: any **K ∈ [2, 64]**. The previous AscendC kernel was **width-4 only** and rejected non-power-of-two `dim`. (vLLM's causal_conv1d uses width 3 — now supported.)


**Results — Ascend 910B2, fp16, K=4** (baseline ÷ PTO; speedup > 1 ⇒ PTO faster):

| metric | vs current sgl AscendC | vs PR-555 |
|---|--:|--:|
| **e2e** | median **2.50×** (1.74–8.92×) | median **1.49×** (1.03–1.90×) |
| **kernel-only** | median **2.48×** (1.62–8.65×) | median **1.49×** (1.03–1.90×) |

At small/prefill shapes the lead over sgl is much larger (up to **~9× e2e / ~24× kernel-only**) because the AscendC kernel's launch overhead dominates there; at scale everything is HBM-bandwidth-bound and the gap settles at a steady ~2.5×.
