## Upstream description

# NPU: graph-safe `split_qkv_rmsnorm_rope_pos_cache_half_npu` and op test

## Summary

- **Kernel / Python wrapper:** Remove host-side `positions` validation that forces NPU sync and breaks `torch.npu.graph` capture. Clamp each row’s position index inside the Triton kernel to `[0, max_seq - 1]` before indexing `cos_sin_cache`.
- **Tests:** Add regression coverage under `tests/python/sgl_kernel_npu/` — torch golden (aligned with split → RMSNorm → RoPE from cos/sin cache), eager vs golden, and `torch.npu.NPUGraph` capture/replay.

## Problem

Host checks such as `(pos < 0).any()` or `.min().item()` on device tensors trigger **device sync**. During **NPU graph capture**, syncing the captured stream is disallowed, so the op could not be used safely inside `torch.npu.graph`.

## Fix

**`python/sgl_kernel_npu/sgl_kernel_npu/norm/split_qkv_rmsnorm_rope_pos_cache_half_npu.py`**

- **Wrapper:** Avoid pre-launch host logic that reads device values back for bounds checks.
- **Kernel:** Load `p` from `positions`, then clamp `p` to `[0, max_seq - 1]` on-device before loading cos/sin rows.

Out-of-range indices are **clamped** for RoPE lookup; callers should still pass valid positions when possible.

## Tests

Location: `tests/python/sgl_kernel_npu/` (e.g. `test_split_qkv_rmsnorm_rope_pos_cache_half_npu.py` or equivalent module name in that tree).

- **Golden:** Reference torch path: split QKV → optional per-head RMSNorm → RoPE using indexed `cos_sin_cache` (same layout as the kernel: cos half + sin half per row).
- **Eager:** Fused API vs golden (FP32 compare with tolerances for BF16).
- **Graph:** Staging buffers, `torch.npu.NPUGraph` + `torch.npu.graph(..., auto_dispatch_capture=True)`, `replay()` vs golden and eager.

Skip or guard when NPU / `torch_npu` is unavailable.
